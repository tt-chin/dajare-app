# AI_SPEC.md

## 1. Purpose

Define how the backend uses Gemini to judge Japanese ダジャレ for children.

The goal is not linguistic perfection.

The goal is to produce:

- Consistent enough judging
- Fun feedback
- A short educational explanation
- Safe output appropriate for children

## 2. Input

Initial request:

```json
{
  "text": "パンダがパンだ！"
}
```

### Input validation

Before calling Gemini:

- Input must be a string.
- Trim surrounding whitespace.
- Reject empty input.
- Set a reasonable maximum length.
- Do not send obviously invalid payloads.
- Unsafe input should be handled safely.

The final maximum length should be implemented as a constant rather than scattered magic numbers.

## 3. Output Contract

The backend must return a normalized object:

```json
{
  "isDajare": true,
  "score": 92,
  "level": "うまい！",
  "word1": "パンダ",
  "word2": "パンだ",
  "comment": "「パンダ」と「パンだ」の音がそっくり！"
}
```

### Fields

#### isDajare

Type:

```text
boolean
```

Meaning:
- Whether the phrase contains recognizable Japanese wordplay / ダジャレ.

#### score

Type:

```text
integer
```

Range:

```text
0–100
```

Meaning:
- Game score, not an objective linguistic measurement.

#### level

Allowed values should preferably be derived by the application/backend from the score rather than freely generated by Gemini.

Initial mapping:

```text
0–39   → さむ～い！
40–69  → いいね！
70–89  → うまい！
90–99  → 天才！
100    → 伝説のダジャレ王！
```

#### word1

Type:

```text
string
```

First word / phrase involved in the wordplay.

#### word2

Type:

```text
string
```

Second word / phrase involved in the wordplay.

#### comment

Type:

```text
string
```

Requirements:

- Japanese
- Short
- Child-friendly
- Positive tone
- Explain the sound/meaning relationship when possible
- Do not insult the child
- Do not contain age-inappropriate content

## 4. Judging Principles

The AI should consider:

1. Similarity of sounds
2. Difference or twist in meaning
3. Whether the wordplay is understandable in Japanese
4. Naturalness
5. Creativity
6. Whether the joke works as a child-friendly ダジャレ

Examples:

```text
布団が吹っ飛んだ
アルミ缶の上にあるみかん
パンダがパンだ
トイレに行っといれ
```

The scoring system does not need to imitate human judges perfectly.

Consistency and fun are more important than false precision.

## 5. Score Philosophy

Avoid making children feel that they failed.

Even when the input is not clearly a ダジャレ:

- Explain gently
- Encourage another try
- Never ridicule the user

Bad:

```text
これは面白くありません。
```

Better:

```text
もうちょっと音が似ていることばを探すと、
ダジャレになりそう！
```

## 6. Gemini Output Strategy

Gemini should return structured data only.

Preferred conceptual model output:

```json
{
  "isDajare": true,
  "score": 92,
  "word1": "パンダ",
  "word2": "パンだ",
  "comment": "「パンダ」と「パンだ」の音がそっくり！"
}
```

The backend should calculate `level` itself from `score`.

Do not let Gemini:

- Choose UI behavior
- Choose animations
- Return executable content
- Control navigation
- Return arbitrary HTML
- Return Markdown that the app renders as trusted content

## 7. Backend Validation

Before returning Gemini output to Flutter:

- Confirm valid JSON / structured result
- Confirm required fields
- Confirm boolean type
- Confirm score is numeric
- Clamp or reject score outside 0–100
- Normalize strings
- Enforce reasonable string length
- Reject clearly unsafe output
- Generate a safe fallback when invalid

## 8. Safety

This is a child-facing application.

The AI must avoid producing or expanding:

- Sexual content
- Graphic violence
- Self-harm content
- Hate/discriminatory content
- Dangerous instructions
- Bullying or insulting content
- Personal-data requests
- Adult-oriented jokes
- Frightening or age-inappropriate explanations

If a child's input is unsafe or inappropriate, do not creatively continue it as a joke.

Return a friendly redirection.

Example:

```text
ほかのことばでダジャレを作ってみよう！
どうぶつや食べもののお題がおすすめだよ。
```

## 9. Prompt Design — Initial Requirements

The production prompt should tell Gemini:

- It is judging Japanese ダジャレ for children.
- Output must follow the required structured schema.
- Feedback must be short.
- Feedback must be positive and age-appropriate.
- Identify the two relevant sounds / words.
- Do not introduce unsafe content.
- Do not ask the child personal questions.
- Do not produce extra prose outside the structured response.

The exact Gemini SDK syntax and structured-output configuration should be implemented according to the currently selected Gemini model and official API capabilities at implementation time.

## 10. Example Cases

### Clear ダジャレ

Input:

```text
パンダがパンだ！
```

Expected style:

```json
{
  "isDajare": true,
  "score": 90,
  "word1": "パンダ",
  "word2": "パンだ",
  "comment": "「パンダ」と「パンだ」の音がそっくり！"
}
```

The exact score may vary within the scoring rules.

### Weak / incomplete wordplay

Input:

```text
ねこがかわいい
```

Expected style:

```json
{
  "isDajare": false,
  "score": 20,
  "word1": "ねこ",
  "word2": "",
  "comment": "「ねこ」と音が似ていることばを見つけると、ダジャレになりそう！"
}
```

### Invalid / empty input

Do not call Gemini when avoidable.

Return an application validation error.

## 11. Future Improvements

Potential later additions:

- Learning explanation
- Alternative hint
- Phonetic analysis
- Evaluation consistency tests
- Curated benchmark set of child-friendly ダジャレ

Do not add these until the MVP judging flow is stable.
